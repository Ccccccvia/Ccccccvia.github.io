## 先问合法性，再问驻留状态

一个地址可以属于合法区域，却暂时没有当前可用的物理页映射。
“这个编号能否使用”和“这一页是否已经驻留 RAM”是两个问题。

| 层次 | 要问的问题 | 示例 |
| --- | --- | --- |
| 地址范围 | 编号能否在这个地址模型中表示？ | 一个可表示的虚拟地址 |
| 区域与权限 | 区域有效吗，允许这次读、写或执行吗？ | 合法区域，但只允许读 |
| 当前映射 | 现在是否有在场且可用的页？ | 按需提供、尚未驻留 |

编号可表示，不等于它已分配给程序；页未驻留，也不等于地址非法。

## Page fault 是一次处理入口

本文讨论常见 x86 分页：页不在场或触及分页保护条件时，硬件可产生缺页异常 `#PF`。
CPU 进入 OS 的异常处理入口，由内核结合区域、权限和页状态判断原因。

```text
访存 → 硬件发现分页条件 → #PF → OS 判断
  合法且可补齐 → 提供页或调整映射 → 重试故障指令
  非法地址或确实不允许的操作 → 报告访问错误
```

可恢复缺页通常对应用透明：补齐成功后，原来的访问可以继续。
常见 x86 的 TLB 未命中本身不等于缺页，硬件可能只需遍历页表。
也不是所有访存异常都属于 `#PF`；地址格式、对齐等问题可能走其他异常入口。

## 一个零页与写时复制的场景

假设程序有一页合法的、允许读写的 4 KiB 匿名内存，采用按需提供策略。
首次读取前，尚未建立当前可用映射；这里选择一种使用共享零页的实现方式。

| 步骤 | 硬件观察 | OS 可做的工作 |
| --- | --- | --- |
| 首次读取 | 页不在场，产生缺页 | 映射只读共享零页，让读取返回零 |
| 随后写入 | 当前硬件映射只读，再次缺页 | 提供私有清零页，建立可写映射 |
| 重试写入 | 新映射在场且可写 | 写入成功，其他零页使用者不受影响 |

第二次缺页属于写时复制（COW）处理，而不是批准任意修改只读内存。
OS 知道该区域逻辑上允许写入，只是当前共享页的硬件权限暂时禁止写。
一般 COW 也可能复制已有的非零内容；零页场景可以直接提供私有清零页。
不同系统或分配策略可能直接提供私有页，不必严格经历上表的两次缺页。

## 哪些缺页需要读盘

| 页面来源或状态 | 典型补齐方式 | 必须从存储读入吗？ |
| --- | --- | --- |
| 合法匿名页首次使用 | 提供清零页 | 不必 |
| 所需文件页已在 RAM 缓存中 | 接回映射 | 不必 |
| COW 的原页已在 RAM 中 | 复制或提供私有页 | 不必 |
| 所需内容仅在 swap、页面文件或磁盘文件中 | 发起 I/O，读入后更新映射 | 需要 |

缺页计数不能直接当作磁盘读取次数。
RAM 缓存中的文件页和磁盘上的文件内容，也不是两份必须同时读取的来源。

## 什么时候会成为段错误

若地址不属于合法区域，或写入确实只读的区域，OS 无法按该访问请求合法补齐。
Unix/Linux 常以 `SIGSEGV` 报告这类访问；Windows 常见的是 Access Violation。
默认或未处理时通常终止进程，并不意味着应用绝无信号或异常处理机制。
只返回同一条指令而不修复原因，通常不能让非法访问成功。

配图对比的是“可补齐”和“非法访问”两条路径，不是所有失败原因的完整清单。
合法页面也可能因内存不足或 I/O 错误无法补齐，不能承诺每个合法缺页都会成功。

## 没崩溃，不代表 C 访问安全

C 的对象边界与生命周期，不等于硬件分页边界。
越界或释放后使用可能仍落在一个已映射、可写的页里，因而悄悄破坏数据。
这些访问可能是未定义行为；没有出现段错误并不能证明程序正确。

页级保护帮助隔离地址空间，但不是逐个对象的内存安全检查器。
